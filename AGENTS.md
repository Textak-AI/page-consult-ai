# Architecture rules
- Site harvest extends website extraction with owner-JWT storage writes and public-host-checked fetches; candidates retain source URLs in existing JSON. clientImages owns automatic source ranking, TreatedImage and design tokens own photographic geometry/treatment; work samples stay upload-only.
- Buyer objection prompts and answered-only selectors live in _shared/buyerObjections; wizard drafts and existing JSON retain pairs, brief/page guards restore verbatim answers, and FAQ proof entries stay beside the final ask.
- Work samples use upload-only structured section content and a shared audited gallery in both renderers; owner-prefixed brand-assets paths preserve existing policies, and detached files are retained for undo/snapshots rather than deleted on section removal.
- Signature presentation lives in src/components/signature; its pure selector stores plans in section content so undo/autosave/publish share the same treatments. Both renderers use SignatureSection; unsourced stats, kickers and CTA terms never render.
- Generated brief prose/JSON and page/section outputs use `_shared/copyClaims.ts` against raw input only; unsupported digit/spelled-number sentences and unstated commitment terms are removed and logged, so generated briefs cannot authorize their own claims.

- Communication Strategy Phase A is extractive and stored inside the existing structured brief/page consultation JSON; the mapper applies it after legacy heuristics, and mechanism suggestions never enter page copy, preserving input provenance and CTA text.

- Edge-handler regression tests evaluate unchanged Deno source in isolated VM contexts with injected imports and local-only DB/provider fakes, so billing/privacy paths are exercised without production exports, credentials, or live side effects.

- Password recovery shares the /reset-password route and redirect helper; only recovery-link/event sessions validated by getUser may show the reset form, and recovery updateUser omits current_password because recovery sessions are exempt.

- Brand-scene generation uses Replicate reference-image predictions and caches durable data URLs, preserving logo input and preventing expiring provider URLs from breaking cached scenes.
- Generated heroes download provider bytes before returning/caching durable bitmap data URLs; legacy cache links are upgraded on read or omitted on failure, so page data never receives a successful temporary image URL.

- Generate's asynchronous brief dispatcher reads current router state through a ref before falling back to the mount snapshot and consultation data, preventing stale render closures without parsing or coercing brief values.
- AI consultant transport translates Anthropic text-block events into OpenAI-compatible SSE deltas and a DONE sentinel because the existing editor consumes that streaming contract.
- Public prospect pages use a service-side display-field projection rather than direct anonymous table reads, so CRM status does not gate sharing and private prospect fields stay protected by existing RLS.- Public preview links resolve through a service-side single-token lookup returning display fields only, so preview_links never needs anonymous read access.
- Lead webhooks: profiles.lead_webhook_url (HTTPS-only) + webhook_deliveries log; delivery via _shared/leadWebhook.ts (5s timeout, 1 retry, never blocks lead capture); test-lead-webhook authenticates and only posts to the caller's own saved URL.
- QuickPivot capture resolves public prospect slugs server-side into owner-scoped quickpivot_leads; prospect_pages and CRM prospects keep independent server-written first-lead markers, claimed atomically before delivery with provider idempotency. The /for/ contact action is separate from existing CTA handlers so navigation is never intercepted.
- Billing actions share create-portal-session; it validates the user and resolves only their stored Stripe customer ID, with a server-configured return URL, so clients cannot select another billing account or redirect target.
- Anonymous session access uses explicit bearer capabilities checked against service-side rows and expiry; demo tokens are session_id values (not record IDs), claimed sessions require their authenticated owner, and consultationAccess keeps authenticated queries unchanged while routing guest ID-scoped queries through guest-session.
- IntelligenceContext preserves its React context identity in Vite hot-update data because mixed component/helper exports can otherwise detach refreshed consumers from a mounted provider.
- Product-page entrance motion goes through GazeReveal with tokens in src/lib/motion; mount only hides the wrapper and all DOM measurement waits for the section to intersect, so page/editor load never runs per-section layout reads synchronously.
- Plan allowances, action costs and Stripe price/pack maps live only in supabase/functions/_shared/planLimits.ts; credit-consuming edge functions charge via track_ai_action before AI work and return 402 limit_reached, and user_usage billing columns are server-write-only (guard trigger), so the client can never grant or skip credits. Pack actions are a persistent balance (actions_purchased) spent after rollover and monthly allowance; charged work runs through runChargedWork so failures refund via service-role refund_ai_action. New page builds charge through charge_page_build, which atomically consumes the per-account free_page_build_used_at flag before charging; other charged functions wrap their handler in withCharge.
- The PageConsult badge on tenant pages is decided server-side from the owner's user_usage.plan_tier (page_shows_badge RPC for /p/, ownerShowsBadge in get-prospect-page and get-preview-link), so clients never choose it and plan changes apply on next load.
- Editor section-list changes go through src/lib/editor/sectionOps (immutable, order renumbered to array index; leading hero and trailing final-cta pinned) and added-section content through sectionFactory (brief-verbatim or [bracket] placeholders), so undo/autosave capture them and editor indices match render order.
- Editor tablet/mobile preview renders LivePreview through a same-origin iframe portal (DevicePreviewFrame) that mirrors app stylesheets, so viewport media queries apply exactly as on the published page; device choice is session-only state.
- Generated copy is shortened only via src/lib/text/truncate (truncateAtBoundary: sentence end past half the limit, else last word boundary, never mid-word) so length caps never damage real copy.
- Owner colour/font overrides live in landing_pages.styles.theme and resolve through src/lib/editor/pageTheme (shared by LivePreview and PublicPageRenderer, override > brand > industry); hero layout is the hero section's content.composition, so both ride the existing undo/autosave/publish snapshot.
- Product-page section type/spacing/radius values come only from src/lib/design/tokens.ts (derived from dominant existing usage); headline wrap guard lives in index.css scoped to .live-preview-container/.page-theme-root, so section components never carry their own px/clamp magic numbers.
- Logos are accepted only through src/lib/logoAudit (load+decode, size, social-image, transparent/solid-pixel rules) at extraction/upload, and every logo slot renders through useUsableLogo, so failing or stale logo URLs collapse instead of showing broken or placeholder images.
- Copy register (style-only rules + hype lexicon) lives only in supabase/functions/_shared/copyRegister.ts; every copy-generating edge function appends COPY_REGISTER_RULES to its system prompt and runs log-only logRegisterViolations on parsed output, so the standard has one source and residual rate is observable without rewriting copy. Brief and page-content also append PROVENANCE_RULES and run log-only logProvenanceViolations over every qualitative field against the user input only (never the brief).
- Section tier wrappers carry no padding; each section owns its vertical padding (sectionY dense, sectionYCompact for sparseSectionTypes) and surfaces come from sectionSurface in src/lib/design/tokens.ts, so section backgrounds meet flush and heroes size to content.
- Page composition runs every page structure through src/lib/composition/arc (hero → problem → guide → plan → outcome → proof → CTA); a missing slot is inserted only when its source field exists, and the decision log is printed, so sparse briefs still tell a story without padding.
- Brand accent colour is applied only through accentFor(ACCENT_SLOTS) in src/lib/design/tokens.ts (eyebrow, timeline marker, pull-quote rule, CTA); image-bearing heroes render the photo under a scrim and hide on load failure, so the typographic hero is the fallback.
- Hero imagery resolves through useUsableImage in every hero style (failed loads collapse to the typographic fallback); the hero's largest element is never motion-hidden so LCP doesn't wait on entrance motion; a page's only second image is the pull-quote's optional supportingImage.
- Extracted-string display casing goes only through src/utils/formatForDisplay (formatForHeadline for headlines, formatForSentence mid-sentence); raw toLowerCase/title-casing on extracted copy mangles acronyms (FDA, 510(k)) and is never used in templates.
- resolveIndustry ranks scored classification above stated-text keyword matches (high beats all keyword matches, medium beats sub-threshold ones; exact stated match still wins); callers with an IndustryDetection always pass variant+confidence (manuallyConfirmed → high).
- One visual director: applyArtDirectorDirectives emits the complete per-section plan (sectionBackground on EVERY section, mode derived from that background, pageMode stamped uniformly); SDI mode is only a fallback for legacy pages via artDirectedMode. Renderers and section components obey content.sectionBackground/mode and never re-decide surfaces from SDI or industry defaults.
- Micro-interactions come only from src/lib/motion/micro.ts tokens: MagneticCta wraps ONLY the strategy's primary ask (plus pc-cta-primary sweep class); StatCountUp animates only already-sourced stats and always settles on the exact original text; CSS draws (pc-connector, signature-rule) run off GazeReveal's data-reveal-armed/data-revealed attributes so no-JS pages stay static. Everything is transform/opacity-only and bails under prefers-reduced-motion. Pages that MOUNT hidden (background tab, occluded window) defer reveals until first shown and animate only below-the-fold sections — never disable motion for the visit. Grain is decided by pageWantsGrain (section industry key wins over stored raw labels).
- Surface rhythm belongs to the art director (applySurfaceRhythm in artDirectorBrief): adjacent light sections alternate light/tinted and the close on a light-led page is the one deep moment. Both renderers apply it at display time (withSurfaceRhythm preserves editor array indices). Deep surfaces are brand-derived (color-mix of the primary into near-black) and 'tinted' is always a LIGHT surface.
- Hero photo prompts come from src/lib/heroImagePrompt (subject = the consultation's industry/offer/stated value; the art director supplies mood only); image cache keys hash the prompt, never a possibly-missing consultation id.
- Hero subheadline = the stated outcome (strategy.oneLiner) re-addressed to the reader via toReader (their->your), and never a line with >=60% content-word overlap with the headline (wordOverlap); a restating subheadline is dropped rather than shown.
- Stated input that reaches the page verbatim passes through src/lib/text/copyEdit (copyEditSections, last mapper pass): mechanical slip fixes and capitalization only - never rewording, never new claims. Commitment language (guarantee/money-back/risk-free/warranty) must be stated in input; copyClaims.unsupportedCommitment gates headlines and guarded copy.
- How-it-works renders only when the input states a process (processDescription or methodologySteps); the brief may phrase stated steps but never design one, and there is no generic industry fallback.

## Type-checking
- Root `tsconfig.json` has `"files": []` — `npx tsc --noEmit` checks NOTHING. Use `npm run typecheck` (`tsc -p tsconfig.app.json`). `npm test` now runs it before the bun suite.

## Work-gallery nudge
- `WorkNudgeBanner` (editor only) suggests a Work Samples section when the business is a visual trade or we found client-site photos, and no gallery exists. Upload-only: the gallery never takes stock or generated images — those would present someone else's work as theirs. Inserts after the payoff (`workGalleryInsertAt`). Dismissal is per page in localStorage.
- Every live mapBriefToSections call passes `consultationData` (nav consultationData merged with strategicData.consultationData). Without it the provenance guards see `{}` — how-it-works never renders and commitment checks run blind. A test enforces it.
- The communication-strategy reframe owns the hero headline only at headline length (isHeadlineLength: ≤90 chars, ≤14 words); a positioning paragraph leaves the brief headline in place.
- FAQ questions render in the buyer's voice via toPageQuestion (canonical interview prompts only); answers stay verbatim.
- Abstract hero textures are never generated or shown: no archetype asks for 'ambient-texture', Generate skips it, and HeroCenteredType ignores stored generated (data: URL) textures. The typographic hero's atmosphere is brand-derived CSS only (primary-colour light field + fading grid). Photos of the actual business remain the only generated hero imagery.
- Page Chat (floating editor chat, `ConsultantChat` → `page-chat` edge function) edits existing sections and adds new ones as reviewed proposals. Contract and guards live in `_shared/pageChat.ts`: the model sees copy only (copyOnly), proposals are guarded by guardCopyClaims against owner input + current page copy + the owner's chat messages, emptied fields are pruned (original copy stays), adds are limited to CHAT_ADDABLE_TYPES (Add Section menu minus upload-only galleries). The editor applies them via `src/lib/editor/pageChatOps` (mergeCopy keeps design/media keys; adds seeded by sectionFactory and inserted through sectionOps). Charged 1 action per message (section_chat); no auto-analysis on open. consultant-chat is retired and now requires a JWT.
- One AI surface in the editor: a section's AI (sparkle) button opens Page Chat focused on that section (LivePreview `onAskPageChat` → ConsultantChat `focus`; the prompt gets a FOCUS line). The legacy SectionAIChat/modify-section path stays only as a fallback and is guarded by guardCopyClaims against the section's own copy + the owner's request.
- Publishing writes published_pages first, then marks landing_pages published; landing_pages.slug is UNIQUE, so on a clash the update retries without the slug instead of failing silently (which left live pages "In Progress" on the dashboard).
- Never pass a `Content-Type` header to `supabase.functions.invoke`: supabase-js then sends the body as-is ("[object Object]"), and the function answers 400 "Invalid JSON". Let invoke set auth and JSON itself (this broke stock image search).
- Preview and Share both go through src/lib/editor/previewLink (crypto tokens; /preview/:token takes a token, never a slug).
- Section "Regenerate" buttons open Page Chat focused on that section with a prefilled rewrite request; the legacy generate-content regenerate_section path invented offers and is no longer reachable from the editor.
- Every image generator returns bytes, never provider URLs: `_shared/durableImage.ts` is shared by generate-hero-images and generate-section-image (section images used to store replicate.delivery links that expire within hours).
- Naming: PageConsult AI is a product of Hyperbrand Creative, Ltd. "StrataQuest" is retired everywhere (company and methodology). Method labels read "PageConsult Method"; exported blueprints read "Strategy Blueprint" with "PageConsult AI by Hyperbrand Creative, Ltd". A test fails on any StrataQuest string in src/ or supabase/functions/.

## Website-first path (2026-10-31)
- Entry: /wizard/form → BrandExtractor (extract-brand) → WebsiteAnalyzer ("Let PageConsult Fill It In": analyze-website + extract-website-intelligence in parallel) → StrategicConsultation prefilled via `src/lib/websiteFirst.ts` `websiteFirstPrefill` → same steps/brief/mapper as the hand-typed wizard.
- Verbatim contract lives in `supabase/functions/_shared/siteExtraction.ts`: analyze-website returns `offers[]`, `ctaLabels[]` (picked from harvested button/link labels) and `industryClassification` (IndustrySelector labels + confidence); `sanitizeSiteAnalysis` drops any offer/CTA/testimonial/proof not found exactly on the site. The model never suggests a CTA or offer; missing ones become visible gaps. mainOffer/offerIncludes/ctaText prefill from those verbatim fields; `websiteIntelligence.siteOffers/siteCtaLabels` reach the brief prompt, and `pinStatedCopy` pins brief.ctaText to the stated CTA.

- Industry: `resolveSiteIndustry` ranks the scored pick against the stated text through resolveIndustry and prefills industryCategory/industrySubcategory/industry exactly as the IndustrySelector writes them. `INDUSTRY_TAXONOMY` must mirror IndustrySelector (test-guarded).
- Sections: `pinPageEnds` puts hero first and final-cta last on every mapped page; industryLayouts vocabulary (problem-agitate, solution, benefits, stats) is aliased; missing SECTION_HEADERS keys fall back to the default variant (`headerFor`) instead of throwing.

## Public URL fetches and rate limits (2026-10-31)
- Any edge function that fetches a visitor-typed URL uses `_shared/publicFetch.ts`: `publicUrl()` refuses localhost, private/link-local IPs, IP literals in integer/hex/IPv6 form, bare hostnames, credentials and non-default ports; `publicFetch()` re-checks every redirect hop. Wired into analyze-website, extract-brand, extract-website-intelligence.
- analyze-website runs before sign-in and calls Anthropic, so it is capped at 10 calls per connection per hour via `rateLimit()` on table `edge_rate_limits` (service-role only, RLS blocks clients). The check fails open if the table is missing.
- Pricing pages make no scarcity or discount claims (no spot counters, strikethrough prices or "30% off"); the agency cost/time comparison section is removed.
