# Architecture rules
- Site harvest extends website extraction with owner-JWT storage writes and public-host-checked fetches; candidates retain source URLs in existing JSON. clientImages owns automatic source ranking, TreatedImage and design tokens own photographic geometry/treatment; work samples stay upload-only.
- Buyer objection prompts and answered-only selectors live in _shared/buyerObjections; wizard drafts and existing JSON retain pairs, brief/page guards restore verbatim answers, and FAQ proof entries stay beside the final ask.
- Work samples use upload-only structured section content and a shared audited gallery in both renderers; owner-prefixed brand-assets paths preserve existing policies, and detached files are retained for undo/snapshots rather than deleted on section removal.
- Signature presentation lives in src/components/signature; its pure selector stores plans in section content so undo/autosave/publish share the same treatments. Both renderers use SignatureSection; unsourced stats, kickers and CTA terms never render.
- Generated brief prose/JSON and page/section outputs use `_shared/copyClaims.ts` against raw input only; unsupported digit/spelled-number sentences and unstated commitment terms are removed and logged, so generated briefs cannot authorize their own claims.

- Communication Strategy Phase A is extractive and stored inside the existing structured brief/page consultation JSON; the mapper applies it after legacy heuristics, and mechanism suggestions never enter page copy, preserving input provenance and CTA text.

- Edge-handler regression tests evaluate unchanged Deno source in isolated VM contexts with injected imports and local-only DB/provider fakes, so billing/privacy paths are exercised without production exports, credentials, or live side effects.

- Password recovery shares the /reset-password route and redirect helper; only recovery-link/event sessions validated by getUser may show the reset form, and recovery updateUser omits current_password because recovery sessions are exempt.

- Brand-scene generation uses Replicate reference-image predictions and caches durable data URLs, preserving logo input and preventing expiring provider URLs from breaking cached scenes.
- Generated heroes download provider bytes before returning/caching durable bitmap data URLs; legacy cache links are upgraded on read or omitted on failure, so page data never receives a successful temporary image URL.

- Generate's asynchronous brief dispatcher reads current router state through a ref before falling back to the mount snapshot and consultation data, preventing stale render closures without parsing or coercing brief values.
- AI consultant transport translates Anthropic text-block events into OpenAI-compatible SSE deltas and a DONE sentinel because the existing editor consumes that streaming contract.
- Public prospect pages use a service-side display-field projection rather than direct anonymous table reads, so CRM status does not gate sharing and private prospect fields stay protected by existing RLS.- Public preview links resolve through a service-side single-token lookup returning display fields only, so preview_links never needs anonymous read access.
- Lead webhooks: profiles.lead_webhook_url (HTTPS-only) + webhook_deliveries log; delivery via _shared/leadWebhook.ts (5s timeout, 1 retry, never blocks lead capture); test-lead-webhook authenticates and only posts to the caller's own saved URL.
- QuickPivot capture resolves public prospect slugs server-side into owner-scoped quickpivot_leads; prospect_pages and CRM prospects keep independent server-written first-lead markers, claimed atomically before delivery with provider idempotency. The /for/ contact action is separate from existing CTA handlers so navigation is never intercepted.
- Billing actions share create-portal-session; it validates the user and resolves only their stored Stripe customer ID, with a server-configured return URL, so clients cannot select another billing account or redirect target.
- Anonymous session access uses explicit bearer capabilities checked against service-side rows and expiry; demo tokens are session_id values (not record IDs), claimed sessions require their authenticated owner, and consultationAccess keeps authenticated queries unchanged while routing guest ID-scoped queries through guest-session.
- IntelligenceContext preserves its React context identity in Vite hot-update data because mixed component/helper exports can otherwise detach refreshed consumers from a mounted provider.
- Product-page entrance motion goes through GazeReveal with tokens in src/lib/motion; mount only hides the wrapper and all DOM measurement waits for the section to intersect, so page/editor load never runs per-section layout reads synchronously.
- Plan allowances, action costs and Stripe price/pack maps live only in supabase/functions/_shared/planLimits.ts; credit-consuming edge functions charge via track_ai_action before AI work and return 402 limit_reached, and user_usage billing columns are server-write-only (guard trigger), so the client can never grant or skip credits. Pack actions are a persistent balance (actions_purchased) spent after rollover and monthly allowance; charged work runs through runChargedWork so failures refund via service-role refund_ai_action. New page builds charge through charge_page_build, which atomically consumes the per-account free_page_build_used_at flag before charging; other charged functions wrap their handler in withCharge.
- The PageConsult badge on tenant pages is decided server-side from the owner's user_usage.plan_tier (page_shows_badge RPC for /p/, ownerShowsBadge in get-prospect-page and get-preview-link), so clients never choose it and plan changes apply on next load.
- Editor section-list changes go through src/lib/editor/sectionOps (immutable, order renumbered to array index; leading hero and trailing final-cta pinned) and added-section content through sectionFactory (brief-verbatim or [bracket] placeholders), so undo/autosave capture them and editor indices match render order.
- Editor tablet/mobile preview renders LivePreview through a same-origin iframe portal (DevicePreviewFrame) that mirrors app stylesheets, so viewport media queries apply exactly as on the published page; device choice is session-only state.
- Generated copy is shortened only via src/lib/text/truncate (truncateAtBoundary: sentence end past half the limit, else last word boundary, never mid-word) so length caps never damage real copy.
- Owner colour/font overrides live in landing_pages.styles.theme and resolve through src/lib/editor/pageTheme (shared by LivePreview and PublicPageRenderer, override > brand > industry); hero layout is the hero section's content.composition, so both ride the existing undo/autosave/publish snapshot.
- Product-page section type/spacing/radius values come only from src/lib/design/tokens.ts (derived from dominant existing usage); headline wrap guard lives in index.css scoped to .live-preview-container/.page-theme-root, so section components never carry their own px/clamp magic numbers.
- Logos are accepted only through src/lib/logoAudit (load+decode, size, social-image, transparent/solid-pixel rules) at extraction/upload, and every logo slot renders through useUsableLogo, so failing or stale logo URLs collapse instead of showing broken or placeholder images.
- Copy register (style-only rules + hype lexicon) lives only in supabase/functions/_shared/copyRegister.ts; every copy-generating edge function appends COPY_REGISTER_RULES to its system prompt and runs log-only logRegisterViolations on parsed output, so the standard has one source and residual rate is observable without rewriting copy. Brief and page-content also append PROVENANCE_RULES and run log-only logProvenanceViolations over every qualitative field against the user input only (never the brief).
- Section tier wrappers carry no padding; each section owns its vertical padding (sectionY dense, sectionYCompact for sparseSectionTypes) and surfaces come from sectionSurface in src/lib/design/tokens.ts, so section backgrounds meet flush and heroes size to content.
- Page composition runs every page structure through src/lib/composition/arc (hero → problem → guide → plan → outcome → proof → CTA); a missing slot is inserted only when its source field exists, and the decision log is printed, so sparse briefs still tell a story without padding.
- Brand accent colour is applied only through accentFor(ACCENT_SLOTS) in src/lib/design/tokens.ts (eyebrow, timeline marker, pull-quote rule, CTA); image-bearing heroes render the photo under a scrim and hide on load failure, so the typographic hero is the fallback.
- Hero imagery resolves through useUsableImage in every hero style (failed loads collapse to the typographic fallback); the hero's largest element is never motion-hidden so LCP doesn't wait on entrance motion; a page's only second image is the pull-quote's optional supportingImage.
